# Design

The main decision is to compute every stat from a single streamed `git log --numstat` run, parsed incrementally and folded into a `StatsCollector` that keeps only tallies (per file, per day, per word, per author) and never the commits themselves. Each commit is framed with ASCII record and unit separators in `--format`, so multi-line message bodies cannot be mistaken for numstat lines, and git is spawned without a shell so paths, branch names and author patterns are never interpreted. The upside is one process, flat memory on six-figure histories, sub-second runs on a thousand-commit repo, and zero runtime dependencies beyond `commander` and `picocolors`. The trade-off is that anything git does not put in that one log is out of reach: there is no blame, so "lines you own today" is not available; renames are attributed to the new path only, so a file's history before a move counts under its old name; and authors are grouped by their `.mailmap`-aware display name rather than email, which merges one person's work and personal addresses but would also merge two different people who share a name.
